sed substitutions every developer should memorize

If you spend any time in a terminal, sed is one of those tools that pays back the investment immediately. The substitution command in particular — s/find/replace/ — handles 80% of the text manipulation tasks you'd otherwise fire up a script or open a GUI for. Here are the patterns worth keeping in muscle memory.

The Basic Structure

Before the patterns, a quick refresher. The substitution syntax is:

sed 's/PATTERN/REPLACEMENT/FLAGS'

Common flags: g replaces all occurrences on a line (not just the first), i makes the match case-insensitive, and 2 (or any number) targets a specific occurrence. On macOS, remember to add '' after -i for in-place edits — GNU sed on Linux doesn't require it, which is a fun way to waste twenty minutes if you switch between machines.

Substitutions You'll Use Weekly

Replace the first occurrence on each line

sed 's/foo/bar/' file.txt

Simple, but worth being explicit: without g, this only replaces the first match per line. That matters when your lines have repeated tokens and you only want to touch the leading one.

Replace all occurrences globally

sed 's/foo/bar/g' file.txt

The workhorse. You'll use this to rename things across config files, swap environment variable names, fix consistent typos in docs.

Edit a file in place

# Linux
sed -i 's/localhost/production.db/g' config.yml

# macOS
sed -i '' 's/localhost/production.db/g' config.yml

No temp file gymnastics. Just be aware there's no undo — run it without -i first to preview output.

Case-insensitive replacement

sed 's/error/ERROR/Ig' log.txt

Handy when you're normalizing inconsistent casing across log files or user-generated content. The I flag handles this in GNU sed; on BSD/macOS sed, use lowercase i after the delimiter.

Delete lines matching a pattern

sed '/^#/d' config.conf

This strips comment lines starting with #. Useful for piping a cleaned-up config somewhere without modifying the original. Combine with -i to strip all comments from a file permanently — though you probably want a backup first.

Strip trailing whitespace

sed 's/[[:space:]]*$//' file.txt

A constant need when dealing with copy-pasted code, CSV exports, or files edited on Windows. The [[:space:]] POSIX class catches tabs too, not just spaces.

Remove blank lines

sed '/^$/d' file.txt

Collapses files with excessive whitespace. Combine it with the trailing-whitespace strip to fully normalize a messy file in one pipe.

More Surgical Patterns

Capture groups and back-references

sed 's/\(.*\):\(.*\)/\2:\1/' pairs.txt

This swaps the two sides of a colon-delimited pair. In GNU sed you can use -E for extended regex and drop the backslashes on the parentheses:

sed -E 's/(.*?):(.*)/\2:\1/' pairs.txt

Back-references are where sed starts earning real respect. Use them to reformat dates, restructure CSV columns, or rearrange function argument order across a codebase.

Add a prefix to every line

sed 's/^/    /' code.txt

Indents every line by four spaces. Useful when you're embedding output into Markdown or documentation and need consistent indentation fast.

Add a suffix to every line

sed 's/$/,/' items.txt

Turn a plain list into a comma-appended list in one shot. Combine with head/tail tricks to handle the trailing comma problem for SQL inserts.

Replace only on lines matching a pattern

sed '/DEBUG/s/false/true/g' app.conf

Address filtering. This only runs the substitution on lines that contain DEBUG. It's the feature most developers don't reach for until they've already written an ugly awk pipeline to do the same thing.

Chaining Substitutions

You don't have to run multiple sed calls. Use -e to chain expressions:

sed -e 's/foo/bar/g' -e 's/baz/qux/g' file.txt

Or, if you're doing a lot at once, drop them into a script file:

sed -f transforms.sed file.txt

Each line in transforms.sed is one expression, no -e required.

The One Flag to Not Forget

Run without -i and redirect to a new file when you're unsure:

sed 's/old/new/g' original.txt > modified.txt

Non-destructive, diff-able, and you still have the original. Automate with confidence once the output looks right. That's the workflow that keeps sed useful without being dangerous.
