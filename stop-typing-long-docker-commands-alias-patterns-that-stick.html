Stop typing long docker commands: alias patterns that stick

If you've typed docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}" more than twice this week, you're wasting keystrokes. Docker's CLI is powerful but verbose by design — it optimizes for clarity, not speed. That's your job. A handful of well-chosen aliases will cut your daily Docker typing by a significant margin without requiring any new tools or plugins.

The core principle: alias what you actually type

Don't copy someone else's alias file wholesale. Most of it won't match your workflow. Instead, open a new terminal, run history | grep docker | awk '{print $2, $3}' | sort | uniq -c | sort -rn | head -20, and look at your own patterns. Alias the top results. Here's mine as a starting point:

# ~/.zshrc or ~/.bashrc

alias dk='docker'
alias dkps='docker ps'
alias dkpsa='docker ps -a'
alias dkst='docker stats --no-stream'
alias dkl='docker logs --tail=100 -f'
alias dki='docker images'
alias dkrm='docker rm $(docker ps -aq)'
alias dkrmi='docker rmi $(docker images -q)'
alias dkprune='docker system prune -af --volumes'

Short, predictable, easy to remember. The dk prefix keeps everything grouped in your autocomplete.

Container lifecycle shortcuts

Starting, stopping, and exec-ing into containers is where you spend most of your time during development. These patterns cover the common cases:

# Stop all running containers
alias dkstop='docker stop $(docker ps -q)'

# Run a throwaway container with your current directory mounted
alias dkrun='docker run --rm -it -v "$(pwd)":/workspace'

# Exec into a running container interactively
dkex() {
  docker exec -it "$1" "${2:-sh}"
}

That dkex function is more useful than a plain alias because it takes arguments. Call it with dkex my-api bash or just dkex my-api to default to sh — handy for Alpine-based images where bash isn't installed.

The format flag problem

Docker's default ps output is wide and truncated in annoying places. You almost always want a custom format, but typing --format every time is painful. Fix it two ways:

Option 1: alias with baked-in format

alias dkps='docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"'

Option 2: Docker config file (persistent, no alias needed)

# ~/.docker/config.json
{
  "psFormat": "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"
}

The config file approach is better if you work across multiple machines — commit it to your dotfiles repo and you're done. The alias wins if you want context-specific formats per project.

Docker Compose deserves its own layer

If you use Compose daily (and you probably do), these save real time:

alias dc='docker compose'
alias dcu='docker compose up -d'
alias dcd='docker compose down'
alias dcr='docker compose restart'
alias dcl='docker compose logs --tail=100 -f'
alias dcb='docker compose up -d --build'

# Rebuild a single service without stopping others
dcbuild() {
  docker compose up -d --build "$1"
}

Notice dcu defaults to detached mode. If you want foreground output, just run dc up — you still have the flexibility.

Cleanup commands you'll actually remember

Disk cleanup is the thing everyone does manually until they run out of space. Alias it now:

# Remove dangling images only (safer)
alias dkclean='docker image prune -f'

# Nuclear option: remove everything unused
alias dknuke='docker system prune -af --volumes'

# See what's eating disk
alias dkdf='docker system df'

Keep dkclean and dknuke distinct. You want a speed bump before running the destructive one.

Making aliases stick across machines

The reason most alias setups fail isn't the aliases themselves — it's that they live only on one machine. Fix this with a dedicated file:

  • Create ~/.docker_aliases and put all Docker aliases there
  • Source it from your .zshrc or .bashrc: [ -f ~/.docker_aliases ] && source ~/.docker_aliases
  • Track it in your dotfiles repo alongside your .gitconfig and .vimrc
  • Use a tool like chezmoi or bare git repo to sync dotfiles across machines

This way your aliases are version-controlled, portable, and independent of your shell config clutter.

One rule to keep it maintainable

Aliases rot. You add them when you need them, forget they exist, and six months later you have 40 aliases and use 8. Set a calendar reminder every quarter to run that history | grep docker command again. Delete anything that doesn't show up in your top 20. The best alias file is the one you've actually memorized — and you can only memorize a small number of things.

Start with five aliases today. Add more only when you catch yourself typing the same thing twice in one session. That friction is the signal.
