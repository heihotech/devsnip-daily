Making ls readable again with exa and aliases

If you've been staring at the same wall of monochrome text from ls for years, you're leaving a lot of information on the table. exa is a modern replacement written in Rust that adds color, icons, Git status, and a saner default output — without making you learn a new mental model. Pair it with a few shell aliases and your terminal file browsing gets meaningfully better in about five minutes.

Installing exa

On macOS, Homebrew is the fastest path:

brew install exa

On Ubuntu/Debian:

sudo apt install exa

On Arch:

sudo pacman -S exa

Once installed, run exa in any directory. You'll immediately see color-coded output: directories in blue, executables in green, symlinks in cyan. No flags needed to get there — it's the default.

The flags you'll actually use

Before setting up aliases, it helps to know which flags earn their keep day-to-day.

Long format with human-readable sizes

exa -lh

This is the equivalent of ls -lh, but the output is color-coded by column — permissions in one color, file size in another, timestamps in another. Much easier to scan quickly.

Tree view

exa --tree --level=2

This replaces the need to reach for tree (which you may or may not have installed). The --level flag keeps it from dumping your entire node_modules into the terminal.

Git status column

exa -lh --git

Inside a Git repo, this adds a two-character column showing each file's Git status — whether it's untracked, modified, staged, or clean. You get a quick snapshot of what's changed without running git status separately.

Show hidden files

exa -lha

Same as ls -lha. The -a flag includes dotfiles. Nothing surprising here, which is the point — the mental model transfers directly.

Setting up useful aliases

The real payoff comes from making these flags your defaults. Open your ~/.bashrc or ~/.zshrc and add a block like this:

# Replace ls with exa
alias ls='exa --color=always --group-directories-first'
alias ll='exa -lh --color=always --group-directories-first'
alias la='exa -lha --color=always --group-directories-first'
alias lt='exa --tree --level=2 --color=always'
alias lg='exa -lh --git --color=always --group-directories-first'

A few notes on what's in here:

  • --group-directories-first sorts directories above files, which matches how most people actually think about a folder's contents.
  • --color=always forces color even when piping, which you sometimes want. If you pipe to grep and color codes get in the way, you can drop this flag or add a no-color alias separately.
  • lg is the one you'll use constantly inside project repos — it combines the long view with the Git column so you can see file sizes and modified status at a glance.

After editing, reload your shell config:

source ~/.zshrc   # or ~/.bashrc

A practical example

Say you're jumping into an unfamiliar project. Running lg in the root gives you:

  • Directory structure with folders listed first
  • File sizes so you can immediately spot a 40MB log file that shouldn't be there
  • Git column showing which files have been modified since the last commit
  • Color-coded permissions so symlinks and executables stand out

That's four useful signals in a single command you'd have typed anyway.

One potential gotcha

If you're on a system where you don't have exa installed (a remote server, a Docker container, a colleague's machine), your muscle memory for ll will fail. The fix is to make your aliases conditional:

if command -v exa &> /dev/null; then
  alias ls='exa --color=always --group-directories-first'
  alias ll='exa -lh --color=always --group-directories-first'
  alias la='exa -lha --color=always --group-directories-first'
else
  alias ll='ls -lh'
  alias la='ls -lha'
fi

This way your dotfiles work on any machine without breaking anything. The command -v check is portable across bash and zsh.

Worth knowing: eza

Development on the original exa repo stalled for a while and a community fork called eza has taken over active maintenance. It's a drop-in replacement with the same flags. If you're setting this up fresh, check whether your package manager has eza available — it may be the more actively maintained option going forward. Either way, the aliases above work unchanged.

Five minutes of setup, and ls stops being a chore you tolerate and starts being something that actually helps you read a directory.
