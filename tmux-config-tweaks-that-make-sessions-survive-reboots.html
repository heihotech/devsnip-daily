tmux config tweaks that make sessions survive reboots

If you've ever lost a carefully arranged tmux session to a reboot or accidental logout, you know the pain of rebuilding your workspace from scratch. The good news: a handful of config tweaks and one solid plugin will make your sessions persist across reboots with almost zero manual effort. Here's exactly what I run.

The Core Tool: tmux-resurrect and tmux-continuum

The heavy lifting comes from two plugins by Bruno Sutic. tmux-resurrect saves and restores sessions manually. tmux-continuum automates that save on a timer and triggers restore on tmux server start. Use both together.

If you're already using TPM (tmux Plugin Manager), drop these into your ~/.tmux.conf:

set -g @plugin 'tmux-plugins/tpm'
set -g @plugin 'tmux-plugins/tmux-resurrect'
set -g @plugin 'tmux-plugins/tmux-continuum'

# Auto-restore last saved environment on tmux start
set -g @continuum-restore 'on'

# Save interval in minutes (default is 15)
set -g @continuum-save-interval '10'

# Initialize TPM (keep this at the very bottom)
run '~/.tmux/plugins/tpm/tpm'

Then hit prefix + I to install. After the next reboot, tmux will reload your windows, panes, and working directories automatically.

Restore Pane Contents Too

By default, resurrect saves layout and working directories but not what's actually on your screen. Enable pane content capture:

set -g @resurrect-capture-pane-contents 'on'

This writes scrollback buffer snapshots to disk. It's not perfect for interactive programs, but for editors and log tails it's genuinely useful to see where you left off.

Restoring vim and neovim Sessions

tmux-resurrect has built-in support for restoring vim and neovim with their sessions intact, but you need to opt in:

set -g @resurrect-strategy-vim 'session'
set -g @resurrect-strategy-nvim 'session'

This tells the plugin to call vim -S with your saved session file instead of just reopening a blank editor. You'll want to pair this with a vim session plugin like vim-obsession to make sure the session file stays current.

Keep tmux Running After Logout

The plugins handle restore, but they can't help if tmux itself dies because your system killed the server on logout. On Linux with systemd, the fix is to enable lingering for your user:

loginctl enable-linger $USER

This keeps user processes alive after logout. Combine it with a small systemd user service to start tmux automatically:

# ~/.config/systemd/user/tmux.service
[Unit]
Description=tmux session
After=network.target

[Service]
Type=forking
ExecStart=/usr/bin/tmux new-session -d -s main
ExecStop=/usr/bin/tmux kill-server
KillMode=none
Restart=on-failure

[Install]
WantedBy=default.target
systemctl --user enable tmux.service
systemctl --user start tmux.service

Now tmux starts on boot, continuum restores your layout, and you just SSH in and attach with tmux a.

A Few Quality-of-Life Config Additions

While you're in ~/.tmux.conf anyway, these small tweaks pay dividends:

  • Increase history limit — the default 2000 lines is too low for real work:
set -g history-limit 50000
  • Set a fast escape time — fixes the annoying delay when pressing Escape in vim:
set -sg escape-time 10
  • Enable mouse support — useful for scrolling and pane resizing without keyboard acrobatics:
set -g mouse on
  • Renumber windows automatically — so gaps don't appear when you close a window:
set -g renumber-windows on

Verify Everything Is Working

After setting this up, do a real test before you trust it. Create a session with a specific layout, wait 10 minutes for continuum to autosave, then run:

cat ~/.tmux/resurrect/last

You'll see a plaintext snapshot of your panes, windows, and commands. If it looks right, reboot and watch your workspace come back. The first time it works, it feels like a small miracle.

Where Saves Live

Resurrect stores snapshots in ~/.tmux/resurrect/. Each save is a timestamped file, and last is a symlink to the most recent one. You can manually save anytime with prefix + Ctrl-s and restore with prefix + Ctrl-r — handy if you're about to do something risky and want a checkpoint.

The whole setup takes maybe 15 minutes to get right and then you stop thinking about it. Which is exactly what good tooling should do.
