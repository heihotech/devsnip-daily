The rsync flags that actually matter for backups

Most people discover rsync, run it with -r, call it a day, and then wonder why their "backup" is missing permissions, symlinks, or timestamps. The tool is extremely capable, but the flags are where everything lives. Here's what actually matters when you're using rsync for real backups—not just syncing some files between folders.

The Core Combination: -aAX

Forget -r (recursive). Your default backup invocation should start with -a, which is shorthand for --archive. It bundles -rlptgoD: recursive, symlinks, permissions, timestamps, group, owner, and device files. That covers most of what you need.

But two things -a misses: ACLs and extended attributes. Add them explicitly:

rsync -aAX /source/ /destination/

-A preserves ACLs. -X preserves extended attributes (xattrs)—things like SELinux labels, macOS resource forks, and custom metadata. If you're backing up a Linux server with SELinux enforcing, skipping -X will cause headaches when you restore. If you're on macOS, skipping it can corrupt app-specific metadata.

Human Progress: --progress vs --info=progress2

Running --progress is fine for a handful of files, but for large backups it prints a line per file and floods your terminal. Use this instead:

rsync -aAX --info=progress2 /source/ /destination/

--info=progress2 gives you a single updating line with overall transfer progress—total size, bytes transferred, and speed. Much more useful when you're moving 200GB and want to know if you should go get coffee or just refill your water.

Deletions: Handle with Care

If you want your destination to mirror your source exactly, you need --delete. Without it, files you've removed from the source will pile up forever in the backup.

rsync -aAX --delete /source/ /destination/

That said, --delete is permanent. If you accidentally delete something from source, the next sync wipes it from the backup too. A safer option for most people:

  • --delete-delay: collects deletions and applies them at the end of the transfer, after new files land safely.
  • --backup with --backup-dir: moves deleted/changed files into a separate directory instead of removing them. Good for versioned backups.
rsync -aAX --delete --backup --backup-dir=/backups/deleted-$(date +%F) /source/ /destination/

Now you have a dated folder of everything that got overwritten or removed in each run. Simple poor-man's versioning.

Network Backups: Compression and Partial Transfers

If you're syncing over SSH or to a remote host, two flags become important.

-z enables compression in transit. It's not always a win—if your files are already compressed (videos, zip archives, already-compressed databases), you're burning CPU for nothing. But for source code, logs, and plain text, it helps a lot on slow connections.

--partial keeps partially transferred files if the connection drops. Without it, rsync deletes the incomplete file and restarts from scratch next run. Pair it with --append-verify on large files to resume and checksum:

rsync -aAX -z --partial --append-verify user@remote:/source/ /local/backup/

Checksum Verification: -c

By default rsync skips files where the size and modification time match the destination. That's fast, but it won't catch silent corruption. The -c flag forces rsync to compute checksums on both sides and transfer if they differ.

Don't use this every run—it reads every byte on both sides and is slow. Use it periodically, like a monthly verification pass, to make sure your backup is actually intact:

rsync -aAXc /source/ /destination/

The Dry Run is Not Optional

Before any backup job that involves --delete, run it with -n (or --dry-run) and -v first. It shows exactly what would happen without touching anything:

rsync -aAX --delete -nv /source/ /destination/ | head -50

This has saved me from nuking entire directories more than once. It takes ten seconds and costs nothing.

A Solid Default Backup Command

Putting it all together, here's a reasonable starting point for local backups:

rsync -aAX \
  --delete \
  --backup \
  --backup-dir=/backups/archive-$(date +%F) \
  --info=progress2 \
  --exclude='.DS_Store' \
  --exclude='node_modules/' \
  --log-file=/var/log/rsync-backup.log \
  /source/ /destination/

You get full archive preservation, dated rollback for deletions, readable progress, common junk excluded, and a log file for auditing. Adjust the excludes for your environment—maybe add .git/ if you're not backing up repos, or *.tmp files.

rsync is one of those tools where understanding a dozen flags gets you 95% of the way to a production-grade backup. You don't need a dedicated backup application for most use cases—just know what you're passing in.
