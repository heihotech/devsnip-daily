5 grep flags you probably aren't using

You use grep every day. Probably with -r to search recursively, maybe -i for case-insensitive, and -n to get line numbers. That's the core 80%. But there's a handful of flags that don't show up in tutorials and can genuinely save you time when you're deep in a debugging session or parsing logs. Here are five worth adding to your muscle memory.

1. -o — Print only the matching part

By default, grep prints the whole line containing a match. Sometimes you just want the match itself — no surrounding noise. -o does exactly that, one match per line.

echo "Error: connection timeout after 30s" | grep -oE '[0-9]+s'
# Output: 30s

This is especially useful when combined with -E for extended regex. Think extracting all IP addresses from a log file, or pulling every URL out of an HTML blob. Pipe the output to sort | uniq -c and you've got a quick frequency analysis without touching awk or Python.

2. -C — Context lines (above and below)

You probably know -A (lines after) and -B (lines before). -C gives you both at once. Pass it a number and you get that many lines of context on each side of the match.

grep -C 3 "NullPointerException" application.log

Three lines before and three lines after — enough to see what triggered the exception and what happened next. I use this constantly when reviewing stack traces in logs where the actual useful line is two lines above the keyword I'm searching for. -C 5 is my go-to for most debugging sessions.

3. --include and --exclude — Filter by filename during recursive search

When you're searching recursively through a project, you often don't care about minified JS, vendored dependencies, or test fixtures. Instead of post-filtering with more pipes, just tell grep upfront which files to look at.

# Only search Python files
grep -r "TODO" ./src --include="*.py"

# Ignore generated files
grep -r "API_KEY" . --exclude="*.min.js" --exclude-dir=".git"

--exclude-dir is the one that really matters in practice. Searching a Node project without excluding node_modules? You'll be waiting a while and drowning in results. Stack these flags — they're fully composable.

4. -l and -L — List files, not matches

Sometimes you don't care about the specific lines — you just want to know which files contain (or don't contain) a pattern. -l prints filenames with at least one match. -L prints files with zero matches.

# Which config files are missing the required header?
grep -rL "# managed by terraform" ./infra/

That -L use case is the one people sleep on. It's perfect for compliance checks — find every file that's missing a license header, a required import, a shebang line. Way faster than writing a shell loop to do the same thing.

# Which services have logging configured?
grep -rl "log_level" ./services/

5. -P — Perl-compatible regex

The default regex in grep (even with -E for extended) lacks some features you might reach for without thinking: lookaheads, lookbehinds, non-greedy quantifiers, \d, \w, and so on. -P enables Perl-compatible regular expressions, which unlocks all of that.

# Match lines where "error" appears but "timeout" does not follow it
grep -P "error(?!.*timeout)" server.log

# Extract just the version numbers from a package file
grep -oP '(?<="version": ")[^"]+' package.json

That second example — using a lookbehind to extract the value after a JSON key — is the kind of thing that would otherwise mean firing up Python or jq. It's not always the right tool, but knowing it's there means you reach for the right one faster.

Note: -P isn't available on macOS's default BSD grep. You'll need to install GNU grep via Homebrew (brew install grep, then use ggrep) or use ripgrep, which supports Perl-style regex by default.

Putting it together

These flags aren't exotic — they're in the man page. But most people learn grep for a specific task and stop there. The real payoff is combining them:

grep -rnoP '(?<=password=)\S+' ./config/ --include="*.env" -l

Recursive, line-numbered, match-only, Perl regex, scoped to .env files, listing filenames. That's a lot of useful behavior from one command. Spend ten minutes with man grep and you'll find a few more worth keeping around.
